Factory Inventory Management System

A full-stack demo for factory operations: inventory, orders, demand forecasting, backlog and spending analytics. A Vue single-page app talks to a FastAPI service that serves mock data held in memory. There is no database.

System architecture

Three layers: a browser app, a stateless HTTP API, and JSON files that are read once at startup.

Data flow: a filter change on the Dashboard

Every filtered view follows the same request cycle. The data is read-only, so nothing is ever written back.

  1. User changes a filter in FilterBarIt sets one of four singleton refs in useFilters: period, location, category or status. Every view shares this state.
  2. The view's watch() firesDashboard watches all four filters. Inventory and Demand watch only location and category. Spending watches only period.
  3. getCurrentFilters() builds a params objectThe location filter becomes warehouse and the period becomes month, which is either 2025-03 or Q1-2025.
  4. api.js sends parallel GETsDashboard calls summary, orders, inventory and backlog through Promise.all. Filters set to "all" are left out of the query string.
  5. FastAPI filters the lists held in memoryapply_filters() narrows by warehouse, category and status. filter_by_month() matches the order date against a month or a quarter's three months.
  6. Pydantic validates the response, then it's serialized to JSONTyped endpoints use response_model. Dashboard summary, spending and reports return plain dicts.
  7. The view stores raw data in refs and derives the restComputed properties build KPIs and chart series. useI18n formats values in USD or JPY and translates names.

Things to know before changing code

Gaps found

  • The client calls /api/tasks and /api/purchase-orders, but the server doesn't define them, so those calls return 404. The PurchaseOrder models exist in main.py but have no routes.
  • Backlog.vue exists but isn't registered in the router.
  • Reports.vue skips api.js and hard-codes the API URL.
  • Quarters are hard-coded for 2025 in two places in main.py.

Design constraints

  • Data resets on every restart; nothing is persisted.
  • No authentication. The user in useAuth is mock data.
  • Inventory has no time dimension, so the month filter doesn't apply to it.
  • If you change a JSON file's structure, update its Pydantic model too.
  • Use unique keys in v-for, such as sku or month, never index.
